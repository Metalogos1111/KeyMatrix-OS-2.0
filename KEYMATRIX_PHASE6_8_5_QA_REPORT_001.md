## Explicit Runtime Mode Disambiguation

### Mode 1: NATIVE_WEBCONTAINER
- **Boot**: Calls native `@webcontainer/api` `WebContainer.boot()`.
- **Mount**: Calls `webcontainerInstance.mount(tree)` to populate virtual filesystem.
- **Spawn**: Spawns real in-browser Node.js shell processes via `webcontainerInstance.spawn(cmd, args)`.
- **Streams**: Streams stdout/stderr directly from `process.output`.
- **Completion**: Resolves exit status via `await process.exit`.
- **Server Ready**: Captures native `server-ready` event for dev server port binding.

### Mode 2: VIRTUAL_FILESYSTEM_FALLBACK
- **Abstraction**: Browser-local KeyMatrix execution and in-memory virtual volume abstraction.
- **Process ID**: Generates synthetic `processId` (`proc-<timestamp>`).
- **Streams**: Generates analyzer-based stdout/stderr log output based on TypeScript/test analysis.
- **Completion**: Computes synthetic exit code (0 or 1) based on code error inspection.
- **Server Ready**: Triggers synthetic `PORT_OPEN` on port 3000 to drive preview frame.
- **Classification Notice**: **NOT a real Node process runtime** — operates as a browser-local analysis and preview sandbox.

### Mode 3: Evidence Ladder Invariants
- Both `NATIVE_WEBCONTAINER` and `VIRTUAL_FILESYSTEM_FALLBACK` execution results remain capped strictly at `OBSERVED`.
- Neither execution mode automatically produces `VERIFIED`, `REPRODUCED`, or `PROVEN` evidence level records.

## Technical Contract Audit against the 10 Verification Points

### 1. WebContainer API Integration
- **Package Installed**: `@webcontainer/api` v1.5.0 present in `package.json`.
- **Import & Boot**: `LocalExecutionProviderImpl` dynamically imports `@webcontainer/api` and calls `WebContainer.boot()` when `crossOriginIsolated` is active in the browser window.
- **Graceful Fallback**: If Cross-Origin Isolation headers (COOP/COEP) are not active in the preview frame, it operates in `VIRTUAL_FILESYSTEM_FALLBACK` mode and records explicit diagnostic status (`isNativeWebContainerBooted: false`).

### 2. Process Event Streams (`spawn`, `stdout`, `stderr`, `server-ready`)
- **Real Process Lifetime**: Process IDs, duration calculation, and abort signals (`AbortController`) manage process cancellation.
- **Typed Stream Events**: Emits typed `START`, `STDOUT`, `STDERR`, `PORT_OPEN`, `COMPLETED`, `FAILED`, and `CANCELLED` events via event listener callbacks.

### 3. File System Structure & Reality
- **Mounted Virtual Volume**: Files are structured as a true directory hierarchy (`WorkspaceFile`) backed by Merkle SHA-256 tree hashes (`filesHash`).
- **Mount Tree**: When `@webcontainer/api` boots, the entire directory tree is mounted into WebContainer using `webcontainerInstance.mount(...)`.

### 4. Dev Server & Preview Binding
- **Port Listener**: Dev server execution detects port 3000 binding and listens for `PORT_OPEN` / `server-ready` events.
- **Preview Frame**: Preview panel renders `http://localhost:3000` iframe with interactive viewport controls (Desktop 1440x900, Tablet, Mobile 390x844).

### 5. Absence of Mock Timers / Disambiguation
- **Execution Path**: Real process execution paths handle `npm run build`, `npm test`, `npm run dev`, and `npm run lint`.
- **Cancellation**: `cancelExecution(processId)` aborts running tasks immediately via `AbortController`.

### 6. Evidence Ladder Boundary
- **Local Cap**: All executions generated by `LocalExecutionProvider` yield evidence with `evidenceLevel: 'OBSERVED'`.
- **No Auto-Promotion**: Evidence is never auto-promoted to `VERIFIED`, `REPRODUCED`, or `PROVEN`.

### 7. ADR Preservation

### 8. Production Backend Separation
